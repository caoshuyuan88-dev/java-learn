## 1. 复杂度分析与均摊分析
### 1.1 核心原理
- 只保留最高阶项、忽略常数；空间复杂度只算**额外**空间，递归栈要计入（= 递归深度）；均摊分析指"单次可能 O(n)，n 次总代价 O(n)"，如动态数组扩容、HashMap 扩容、并查集路径压缩。
- 增长阶 `O(1) < O(log n) < O(√n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!)`；规模经验（1 秒 ≈ 10⁸ 次操作）：n ≤ 20 可暴搜/状压、n ≤ 10³ 允许 O(n²)、n ≤ 10⁵ 需 O(n log n)、n ≤ 10⁷ 只能 O(n)。
### 1.2 面试问答
**Q1：如何快速分析一段代码的复杂度？**
A：看循环嵌套层数与每层次数的变化规律（每次减半即 log n）；递归用递推式 `T(n)=aT(n/b)+O(n^d)`。平均与最坏都要说，面试官更爱问"什么数据触发最坏"。
**Q2：均摊与平均的区别？**
A：平均依赖输入概率分布（快排期望 O(n log n) 基于随机化假设）；均摊是**最坏情况下的确定性结论**（任意 n 次操作的总代价上界），但不保证单次都快。空间优化手段：原地交换、双指针、滚动数组降维、位图压缩。
### 1.3 高频追问与陷阱
- 循环内字符串拼接是 O(n²)（Java 用 `StringBuilder` 才是 O(n)）；哈希表 O(1) 是平均，最坏 O(n)。
### 1.4 示例
`for (i=1;i<n;i*=2)` → O(log n)；双层循环且内层倍增 → O(n log n)；朴素斐波那契递归 → O(2ⁿ)，记忆化后 O(n)。
### 1.5 一句话速记
`看最高阶、记递归栈；均摊是确定上界，平均依赖概率。`
## 2. 基础数据结构与复杂度
### 2.1 核心原理
| 结构 | 查找 | 插入 | 删除 | 关键点 |
| --- | --- | --- | --- | --- |
| 动态数组 | O(1) | 尾均摊 O(1)/中间 O(n) | O(n) | 扩容 1.5~2 倍，缓存友好 |
| 单/双向链表 | O(n) | O(1) | O(1) | 反转、环检测、合并是必考三件套 |
| 栈/队列 | — | O(1) | O(1) | 单调栈/双端队列解滑窗最值 |
| 哈希表 | 平均 O(1) | 平均 O(1) | 平均 O(1) | 冲突用链地址法/开放寻址，负载因子 0.75 |
| BST | 平均 O(log n) 最坏 O(n) | 同左 | 同左 | 退化靠平衡树（AVL/红黑树） |
| 堆 | 堆顶 O(1) | O(log n) | O(log n) | 数组实现，**建堆 O(n)** |
| 跳表 | O(log n) 平均 | O(log n) | O(log n) | 实现简单、范围查询友好，Redis ZSet 用它 |
| 并查集 | 近似 O(1) | — | — | 路径压缩 + 按秩合并，复杂度 O(α(n)) |
| Trie | O(词长) | O(词长) | O(词长) | 前缀检索，空间换时间 |
| 图 | 邻接表 O(度)/矩阵 O(1) | O(1) | O(1) | 稀疏图用邻接表 |
### 2.2 面试问答
**Q1：为什么 HashMap 负载因子 0.75、容量是 2 的幂？**
A：0.75 是空间与冲突概率的折中（桶长 ≥8 的概率极低，故树化阈值 8）；容量取 2 的幂可把 `% n` 优化成 `& (n-1)`，扩容时元素要么留原位、要么移到"原位 + oldCap"，无需重算哈希。
**Q2：建堆为什么是 O(n)？**
A：自底向上 heapify 时，高度 h 的节点只有约 n/2^(h+1) 个，总代价 `Σ (n/2^(h+1))·h = O(n)`；逐个插入则是 O(n log n)。
**Q3：并查集两个优化的作用？**
A：路径压缩把查询路径节点直接挂到根；按秩/按大小合并避免树退化成链；两者同时用复杂度为 O(α(n))（实际不超过 4）。
### 2.3 高频追问与陷阱
- 链表找环用 Floyd 快慢指针 O(1) 空间，求入环点时"相遇后一指针回起点、同速再相遇"即为入环点；单调栈存**下标**而非值，便于算宽度。
- 稀疏图 Dijkstra 用堆 O(E log V)，稠密图朴素 O(V²) 反而更优。
### 2.4 示例
`int[] p; int find(int x) { return p[x] == x ? x : (p[x] = find(p[x])); }`（路径压缩）；合并时按秩把矮树挂到高树上。
### 2.5 一句话速记
`数组缓存友好、链表插入廉价、堆建堆 O(n)、并查集近似 O(1)、跳表是平衡树的简单替代。`
## 3. Java 集合与数据结构对应关系
### 3.1 核心原理
| Java 类型 | 底层结构 | 查找 | 插入 | 删除 | 备注 |
| --- | --- | --- | --- | --- | --- |
| `ArrayList` | 动态数组 | O(1) | 尾均摊 O(1) | O(n) | 默认容量 10，1.5 倍扩容 |
| `LinkedList` | 双向链表 | O(n) | 头尾 O(1) | O(1) | 也可当 Deque 用 |
| `HashMap` | 数组+链表/红黑树 | 平均 O(1) | 平均 O(1) | 平均 O(1) | 树化 8、退化 6 |
| `LinkedHashMap` | HashMap + 双向链表 | 平均 O(1) | 平均 O(1) | 平均 O(1) | `accessOrder=true` 即 LRU |
| `TreeMap` | 红黑树 | O(log n) | O(log n) | O(log n) | 有序 + 范围查询 |
| `HashSet` | 基于 HashMap | 平均 O(1) | 平均 O(1) | 平均 O(1) | 去重 |
| `PriorityQueue` | 二叉堆 | 堆顶 O(1) | O(log n) | O(log n) | 默认小顶堆 |
| `ArrayDeque` | 循环数组 | — | 头尾均摊 O(1) | O(1) | **官方推荐栈/队列实现** |
| `ConcurrentHashMap` | 数组+链表/红黑树+CAS | 平均 O(1) | 平均 O(1) | 平均 O(1) | 并发容器，禁 null |
| `CopyOnWriteArrayList` | 数组+写时复制 | O(1) | O(n) | O(n) | 读多写少（见 [../01-Java基础/02-集合框架.md](../01-Java基础/02-集合框架.md)） |
### 3.2 面试问答
**Q1：刷题该用什么容器？**
A：映射用 `HashMap`、需要有序用 `TreeMap`、栈与队列一律 `ArrayDeque`（`Stack` 是同步老类、`LinkedList` 有额外开销）、堆用 `PriorityQueue`、固定范围计数用 `int[26]`/`int[128]` 数组最快。
**Q2：`LinkedHashMap` 与手写 LRU 的差别？**
A：`LinkedHashMap` 设 `accessOrder=true` 并重写 `removeEldestEntry` 即为 LRU，O(1)；面试常要求手写 `HashMap + 双向链表`（见 12.4），要能解释原理而不是只会继承。
**Q3：`PriorityQueue` 的局限？**
A：只能取堆顶、不支持删除任意元素（需惰性删除：出堆时判断是否过期）；需要"取最值 + 删除任意 + 有序遍历"时用 `TreeMap`。
### 3.3 高频追问与陷阱
- `Arrays.asList` 是固定长度视图，`add` 抛 `UnsupportedOperationException`；`List.of` 完全不可变。
- `HashMap` 迭代顺序不稳定，不能依赖；`ConcurrentHashMap.size()` 是估算值（`CounterCell` 分段计数）。
### 3.4 示例
`PriorityQueue<Integer> maxHeap = new PriorityQueue<>((a, b) -> b - a);` 即大顶堆；Top K 用小顶堆，`offer(x)` 后若 size>k 就 `poll()`。
### 3.5 一句话速记
`哈希无序、TreeMap 有序、ArrayDeque 万能栈队列、PriorityQueue 只能取堆顶。`
## 4. 排序算法全对比与手写
### 4.1 核心原理
| 算法 | 平均 | 最坏 | 空间 | 稳定 | 适用 |
| --- | --- | --- | --- | --- | --- |
| 冒泡 | O(n²) | O(n²) | O(1) | 是 | 教学、近乎有序可优化到 O(n) |
| 插入 | O(n²) | O(n²) | O(1) | 是 | **小数组（n<16）首选** |
| 选择 | O(n²) | O(n²) | O(1) | 否 | 交换次数最少 |
| 希尔 | O(n^1.3) | O(n²) | O(1) | 否 | 简单的大数组优化 |
| 归并 | O(n log n) | O(n log n) | O(n) | 是 | 稳定、链表、外排序 |
| 快速 | O(n log n) | O(n²) | O(log n) | 否 | 通用最快，需随机化 |
| 堆 | O(n log n) | O(n log n) | O(1) | 否 | Top K、部分有序 |
| 计数/基数/桶 | O(n+k) 级 | — | O(k)/O(n+k) | 是 | 值域小的整数、定长字符串 |
### 4.2 面试问答
**Q1：快排最坏何时发生、如何避免？**
A：有序或近乎有序且取首/尾为基准时退化为 O(n²)，递归深度 O(n) 还可能栈溢出。避免：随机基准、三数取中、小区间切插入排序、深度超限转堆排。快排不稳定但缓存友好，这是它比归并快的两个关键。
**Q2：为什么 Java 对象排序用 TimSort？**
A：业务排序常要求**稳定**（相等元素保持原序），且真实数据多有部分有序 run，TimSort 能利用它接近 O(n)。边界：需要 O(n) 额外空间；违反契约的 Comparator 会抛 `Comparison method violates its general contract`。
**Q3：海量数据如何排序？**
A：外排序——分块读入、块内排序、写回临时文件，再用最小堆做 **k 路归并**（堆大小是 k，不是数据量）。
### 4.3 高频追问与陷阱
- 稳定性判断：相邻交换且相等不换序的稳定；快排/堆排/选择排序不稳定。
- 堆排是"建堆 O(n) + 每轮调整 O(log n)"，总计 O(n log n)，不要把建堆写成 O(n log n)。
### 4.4 示例
```java
void quickSort(int[] a, int l, int r) {              // 短边递归防栈溢出
    while (l < r) {
        if (r - l < 16) { insertionSort(a, l, r); return; }
        int p = partition(a, l, r);                  // 三数取中选 pivot
        if (p - l < r - p) { quickSort(a, l, p - 1); l = p + 1; }
        else { quickSort(a, p + 1, r); r = p - 1; }
    }
}
void mergeSort(int[] a, int l, int r, int[] tmp) {   // 稳定，O(n) 空间
    if (l >= r) return;
    int m = (l + r) >>> 1;
    mergeSort(a, l, m, tmp); mergeSort(a, m + 1, r, tmp);
    int i = l, j = m + 1, k = l;
    while (i <= m && j <= r) tmp[k++] = a[i] <= a[j] ? a[i++] : a[j++];
    while (i <= m) tmp[k++] = a[i++];
    while (j <= r) tmp[k++] = a[j++];
    System.arraycopy(tmp, l, a, l, r - l + 1);
}
void heapSort(int[] a) {
    int n = a.length;
    for (int i = n / 2 - 1; i >= 0; i--) sift(a, i, n);   // 建堆 O(n)
    for (int i = n - 1; i > 0; i--) { swap(a, 0, i); sift(a, 0, i); }
}
```
### 4.5 一句话速记
`不稳定：快排、堆排、选择；快排怕有序要随机化，Java 对象排序用稳定的 TimSort。`
## 5. 二分查找与边界模板
### 5.1 核心原理
| 场景 | 模板要点 | 返回 |
| --- | --- | --- |
| 精确查找 | `while (l <= r)`，`mid=(l+r)>>>1` | 下标或 -1 |
| 第一个 ≥ target（lower_bound） | `mid=(l+r)>>>1`，`a[m]>=t ? r=m : l=m+1` | l |
| 最后一个 ≤ target | `mid=(l+r+1)>>>1`，`a[m]<=t ? l=m : r=m-1` | l |

要点：`>>> 1` 防溢出；取整方向必须与边界收缩方式匹配，否则死循环。
### 5.2 面试问答
**Q1：二分最常见的 Bug？**
A：`(l+r)/2` 溢出（用 `l+(r-l)/2` 或 `>>>1`）、取整方向与收缩不匹配导致死循环、目标不存在时没想清返回 l 还是 r。
**Q2：旋转数组找最小值？**
A：比较 `a[mid]` 与 `a[r]`：`a[mid]>a[r]` 在右半（`l=mid+1`）、`a[mid]<a[r]` 在左半（`r=mid`）、相等则 `r--`；有重复元素时最坏退化 O(n)。
**Q3：二分答案的思想？**
A：当"x 可行 ⇒ x+1 可行"单调成立时，二分枚举答案并对候选做校验，总 O(n log V)；典型有分割数组的最大值、爱吃香蕉的珂珂、运货能力。
### 5.3 高频追问与陷阱
- 二分不要求数组有序，只要求判定单调；浮点二分用固定迭代次数（如 100 次）避免死循环。
- `Arrays.binarySearch` 未命中时返回 `-(插入点)-1`，不是普通 -1。
### 5.4 示例
```java
int lowerBound(int[] a, int t) {           // 左闭右开，第一个 >= t
    int l = 0, r = a.length;
    while (l < r) { int m = (l + r) >>> 1; if (a[m] >= t) r = m; else l = m + 1; }
    return l;                              // 可能等于 a.length
}
```
### 5.5 一句话速记
`防溢出用 >>>1，收缩方向与取整方向必须一致；二分答案 = 单调判定 + 枚举答案。`
## 6. 双指针、滑动窗口、前缀和与差分
### 6.1 核心原理
| 技巧 | 适用特征 | 复杂度 | 典型题 |
| --- | --- | --- | --- |
| 相向双指针 | 有序数组求两数/三数/盛水 | O(n)/O(n²) | 两数之和 II、三数之和、盛最多水 |
| 同向双指针 | 原地删除、去重、找环 | O(n) | 移除元素、环形链表 |
| 定长滑窗 | 窗口大小固定 | O(n) | 长度 k 子数组最大和 |
| 变长滑窗 | 最长/最短满足条件 | O(n) | 无重复字符最长子串、最小覆盖子串 |
| 前缀和 | 多次区间和查询 | 预处理 O(n)、查询 O(1) | 和为 K 的子数组 |
| 差分数组 | 多次区间加、最后统一查 | 更新 O(1)、还原 O(n) | 航班预订统计、拼车 |
| 单调栈/队列 | 下一个更大、窗口最值 | O(n) | 每日温度、滑动窗口最大值 |
### 6.2 面试问答
**Q1：滑动窗口什么时候能用？**
A：当窗口扩张/收缩与条件单调相关时。模板：`for(right){ 加入 a[right]; while(不满足){ 移出 a[left++]; } 更新答案; }`。边界：含负数时"和"不再单调，滑窗失效，改用前缀和 + 哈希。
**Q2：变长窗口里 while 与 if 的区别？**
A：求**最短**窗口用 `while`（缩小到不满足为止并每次更新答案）；求**最长**窗口常用 `if`（只缩一次，保持长度不减小）。面试要明确说"我在求最长还是最短"。
**Q3：和为 K 的子数组为什么用前缀和 + 哈希？**
A：`pre[j]-pre[i]=K` ⇔ `pre[i]=pre[j]-K`，遍历 j 时查哈希中该值出现次数；初始化 `map.put(0,1)` 覆盖从下标 0 开始的子数组。边界：含负数时该法仍正确（不像滑窗）。
### 6.3 高频追问与陷阱
- 三数之和去重要同时跳过重复的 `i`、`l`、`r`；前缀和用长度 n+1 的数组并令 `pre[0]=0` 可省边界判断；差分数组用 long 防溢出。
### 6.4 示例
```java
int lengthOfLongestSubstring(String s) {          // 变长滑窗模板
    int[] last = new int[128]; Arrays.fill(last, -1);
    int ans = 0, l = 0;
    for (int r = 0; r < s.length(); r++) {
        char c = s.charAt(r);
        if (last[c] >= l) l = last[c] + 1;        // 收缩
        last[c] = r;
        ans = Math.max(ans, r - l + 1);
    }
    return ans;
}
```
### 6.5 一句话速记
`双指针省空间、滑窗省时间、前缀和换查询、差分换更新、单调栈找下一个更大。`
## 7. 回溯与贪心
### 7.1 核心原理
回溯模板：`选择 → 递归 → 撤销选择`；剪枝决定通过率。类型：子集/组合（传 `start` 防重复）、排列（用 `used`）、切割（回文分割）、棋盘（N 皇后、数独）。贪心成立需证明"贪心选择性质 + 最优子结构"，否则必须 DP（0-1 背包是经典反例）。
### 7.2 面试问答
**Q1：回溯的复杂度怎么算？**
A：由解的形态数 × 每个解的构造代价决定：子集 O(2ⁿ·n)、排列 O(n!·n)、组合 O(C(n,k)·k)；剪枝只改善平均，不改变最坏上界。
**Q2：组合问题如何避免重复结果？**
A：同一元素不能重复用就递归传 `i+1`；重复值元素不能产生相同组合就**排序后同层跳过相同值**（`if (i > start && a[i] == a[i-1]) continue;`）。
**Q3：什么时候用贪心？**
A：能证明局部最优可推出全局最优（区间调度按右端点排序、跳跃游戏维护最远可达、分发饼干）；需要权衡多个状态时必须 DP。
### 7.3 高频追问与陷阱
- 撤销选择必须在所有分支后执行；递归过深会 StackOverflow（Java 默认栈约 512KB~1MB），必要时改迭代或加 `-Xss`。
### 7.4 示例
`回溯模板`：`if (满足条件) 记录; for (选择 : 选择列表) { if (!合法) continue; 做选择; dfs(...); 撤销选择; }` —— 组合去重先排序，再 `if (i > start && a[i] == a[i-1]) continue;`。
### 7.5 一句话速记
`回溯 = 选择 + 递归 + 撤销；组合去重靠排序 + 同层跳过；贪心必须有证明，反例否定。`
## 8. 动态规划经典模型
### 8.1 核心原理
| 模型 | 状态定义 | 转移要点 |
| --- | --- | --- |
| 0-1 背包 | `dp[j]` 容量 j 的最大价值 | **容量倒序**，每件只用一次 |
| 完全背包 | 同上 | **容量正序**，可重复选 |
| 分组/多重背包 | 组内选一个 / 有数量上限 | 分组遍历；多重可二进制拆分 |
| LIS | `dp[i]` 以 i 结尾的 LIS 长度 | 朴素 O(n²)；`tails` + 二分 O(n log n) |
| LCS | `dp[i][j]` 前 i/j 个字符 | 相同 +1，不同取 max |
| 编辑距离 | `dp[i][j]` 转换代价 | 相等取左上；否则 1+min(增删改) |
| 股票系列 | `hold[i]`/`free[i]` | 状态机，含冷冻期与手续费 |
| 区间 DP | `dp[l][r]` 区间最优 | 按区间长度递增枚举分割点 |
| 树形 DP | `dp[node][0/1]` | 后序遍历合并子节点 |
### 8.2 面试问答
**Q1：0-1 背包为什么容量倒序？**
A：一维压缩后若正序，会用本轮已更新的 `dp[j-w]`（等于同一物品用多次），退化成完全背包；倒序保证读取的是上一行状态。
**Q2：LIS 的 O(n log n) 怎么做？**
A：维护 `tails`，`tails[i]` 是长度 i+1 递增子序列的最小结尾值；对每个元素二分找第一个 ≥ x 的位置替换，更大则追加，`tails` 长度即答案（注意 tails 不一定是合法子序列）。输出具体序列需记录前驱。
**Q3：DP 与记忆化搜索怎么选？**
A：状态稀疏、转移复杂时记忆化搜索更直观；状态稠密、需要滚动数组优化时自底向上更好，两者复杂度一致（状态数 × 转移代价）。
**Q4：初始化为什么关键？**
A：求"恰好装满"用 -∞ 表示不可达，求"至多"用 0；结果可能溢出，组合数与路径数要用 long。
### 8.3 高频追问与陷阱
- 遍历顺序必须与状态依赖一致：依赖上一行按行正序，依赖左/上按行列正序；空间优化前先写二维版本并讲清"为什么能压成一维"。
### 8.4 示例
```java
int knapsack(int[] w, int[] v, int cap) {           // 0-1 背包，容量倒序
    int[] dp = new int[cap + 1];
    for (int i = 0; i < w.length; i++)
        for (int j = cap; j >= w[i]; j--)
            dp[j] = Math.max(dp[j], dp[j - w[i]] + v[i]);
    return dp[cap];
}
int lengthOfLIS(int[] a) {                          // tails + 二分
    int[] tails = new int[a.length]; int len = 0;
    for (int x : a) {
        int l = 0, r = len;
        while (l < r) { int m = (l + r) >>> 1; if (tails[m] < x) l = m + 1; else r = m; }
        tails[l] = x; if (l == len) len++;
    }
    return len;
}
```
### 8.5 一句话速记
`0-1 背包容量倒序、完全背包正序；LIS 用 tails + 二分；股票用持有/不持有状态机。`
## 9. 图论：遍历、拓扑、最短路与最小生成树
### 9.1 核心原理
| 算法 | 复杂度 | 用途 | 要点 |
| --- | --- | --- | --- |
| BFS | O(V+E) | 无权最短路、网格扩散 | 队列，**入队即标记 visited** |
| DFS | O(V+E) | 连通分量、回溯、环检测 | 递归或显式栈 |
| 拓扑（Kahn） | O(V+E) | 依赖排序、课程表 | 入度 0 入队，输出数 < V 即有环 |
| Dijkstra | O(E log V)（堆） | 非负权单源最短路 | 取最小点松弛邻居 |
| Bellman-Ford/SPFA | O(VE) | 含负权、判负环 | 松弛 V-1 轮 |
| Floyd | O(V³) | 多源最短路 | k 必须在最外层 |
| Kruskal | O(E log E) | MST（稀疏图） | 边排序 + 并查集 |
| Prim | O(E log V) | MST（稠密图） | 堆 + 已选标记 |
### 9.2 面试问答
**Q1：BFS 与 DFS 怎么选？**
A：求最短步数/最少操作用 BFS（逐层扩展首次到达即最优）；求所有方案、连通分量用 DFS/回溯。边界：网格题 BFS 入队即标记，否则重复入队导致超时或爆内存；DFS 在超大网格易栈溢出。
**Q2：Dijkstra 为什么不能有负权边？**
A：它假设"已确定的最短距离不会再被改进"，负权边会让后来的路径更短，破坏贪心正确性；含负权用 Bellman-Ford/SPFA，DAG 上可用拓扑序 + 一次松弛 O(V+E)。Kruskal 与 Prim 的取舍：稀疏图用 Kruskal（边排序 + 并查集），稠密图用 Prim（朴素 O(V²)）。
### 9.3 高频追问与陷阱
- 网格坐标用 `int[][] dirs = {{-1,0},{1,0},{0,-1},{0,1}}` 统一遍历；Dijkstra 允许重复入堆（懒惰删除），出堆时判 `if (d > dist[u]) continue;`。
### 9.4 示例
```java
int[] topoSort(int n, int[][] edges) {              // Kahn 拓扑排序
    List<List<Integer>> g = new ArrayList<>();
    for (int i = 0; i < n; i++) g.add(new ArrayList<>());
    int[] indeg = new int[n];
    for (int[] e : edges) { g.get(e[0]).add(e[1]); indeg[e[1]]++; }
    Deque<Integer> q = new ArrayDeque<>();
    for (int i = 0; i < n; i++) if (indeg[i] == 0) q.offer(i);
    int[] order = new int[n]; int idx = 0;
    while (!q.isEmpty()) {
        int u = q.poll(); order[idx++] = u;
        for (int v : g.get(u)) if (--indeg[v] == 0) q.offer(v);
    }
    return idx == n ? order : new int[0];           // 长度 0 表示有环
}
```
### 9.5 一句话速记
`无权最短路 BFS、非负权 Dijkstra、含负权 Bellman-Ford；拓扑排序输出不足即环。`
## 10. 位运算技巧
### 10.1 核心原理
| 技巧 | 表达式 | 用途 |
| --- | --- | --- |
| 判断奇偶 | `x & 1` | 对负数也正确 |
| 取最低位 1 | `x & -x` | lowbit、树状数组 |
| 清最低位 1 | `x & (x - 1)` | 判断 2 的幂、数 1 的个数 |
| 大小写互换 | `c ^ 32` | 字符处理 |
| 子集枚举 | `for (s = mask; s > 0; s = (s - 1) & mask)` | 状压 DP |
| 位图去重 | `bitmap[x >> 6] \|= 1L << (x & 63)` | 海量整数去重、布隆过滤器思想 |
### 10.2 面试问答
**Q1：`x & (x-1)` 能做什么？**
A：清除最低位的 1，因此 `x & (x-1) == 0` 判断 2 的幂（x>0），循环次数等于二进制中 1 的个数（`Integer.bitCount` 更快）。
**Q2：位运算常见陷阱？**
A：Java 的 int 有符号，`>>` 是算术右移（保留符号位），无符号必须用 `>>>`；移位次数按 32 取模（`1 << 32 == 1`）；`1 << 31` 是负数；long 要用 `1L`；`Math.abs(Integer.MIN_VALUE)` 仍为负。工程用途：权限位、状态标记组合、布隆过滤器、分片索引 `hash & (n-1)`、protobuf 紧凑编码。
### 10.3 高频追问与陷阱
- 异或找唯一出现一次的数：全体异或；"两个只出现一次的数"要先用 lowbit 分组；大数计算必须用 `BigInteger`。
### 10.4 示例
`int lowbit = x & -x;`、`boolean isPow2 = x > 0 && (x & (x - 1)) == 0;`、枚举子集 `for (int s = mask; s > 0; s = (s - 1) & mask)`。
### 10.5 一句话速记
`x&(x-1) 清最低位 1、x&-x 取最低位 1、无符号右移用 >>>、移位次数按 32 取模。`

## 12. 大厂手写代码题
### 12.1 核心原理
手撕环节考察"能否在 20 分钟内写出可运行、边界正确的代码"，并发类题目还会追问"为什么这样写、有没有更优解"。
### 12.2 面试问答
**Q1：单例有哪些线程安全写法、怎么选？**
A：静态内部类（懒加载 + 类加载保证安全 + 无锁）与枚举（防反射与反序列化）最优；DCL 必须加 volatile 防指令重排导致其他线程拿到半初始化对象。
**Q2：生产者-消费者三种写法？**
A：`BlockingQueue`（生产首选）、`wait/notify`（必须 while 判条件）、`ReentrantLock` + 双 Condition（精确唤醒，性能更好）。
**Q3：线程池 execute 的完整流程？**
A：核心线程未满则新建线程 → 队列未满则入队 → 队列满且未到最大线程则新建线程 → 都不满足执行拒绝策略；**不要用无界队列**（会内存溢出且 maxPoolSize 失效）。
### 12.3 高频追问与陷阱
- LRU 用哨兵节点简化边界；LFU 需维护 `minFreq` 与每频次的 LRU 顺序；令牌桶允许突发而漏桶输出恒定；`a ^= b` 交换在生产代码中不推荐。
### 12.4 示例
```java

public class Singleton {
    private Singleton() {}
    private static class Holder { static final Singleton INSTANCE = new Singleton(); }
    public static Singleton getInstance() { return Holder.INSTANCE; }
}
public enum EnumSingleton { INSTANCE }
static volatile Singleton s2;                                    // DCL 的 volatile 必不可少
static Singleton dcl() { if (s2 == null) synchronized (Singleton.class) { if (s2 == null) s2 = new Singleton(); } return s2; }
// 2) 生产者-消费者（ReentrantLock + 双 Condition，精确唤醒；wait/notify 写法必须 while 判条件）

lock.lock();

void execute(Runnable task) {
    if (workerCount < core) { addWorker(task); return; }
    if (queue.offer(task)) return;
    if (workerCount < max) { addWorker(task); return; }
    reject(task);
}

synchronized boolean tryAcquire(int n) {

    if (tokens >= n) { tokens -= n; return true; }
    return false;
}
// 5) LRU：HashMap + 双向链表（带哨兵节点简化边界）
void put(int k, int v) {

}

synchronized void print(int mod, String name) {
    while (n <= 100) { while (n % 2 != mod) { try { wait(); } catch (InterruptedException e) { return; } }
        System.out.println(name + ":" + n++); notifyAll(); }
}
// 7) 阻塞队列（数组 + 双 Condition，put/take 对称）
void put(E e) throws InterruptedException {
    lock.lock();
    try { while (count == items.length) notFull.await();
          items[putIdx] = e; putIdx = (putIdx + 1) % items.length; count++; notEmpty.signal(); } finally { lock.unlock(); }
}
```
**LFU 思路**：`Map<key,Node>` + `Map<freq,LinkedHashSet>` + `minFreq`；访问时把节点移到 freq+1 的桶（同频次按 LRU 淘汰）。**简易 HashMap**：数组 + 链表；`hash = (h = key.hashCode()) ^ (h >>> 16)` 让高位参与运算；下标 `hash & (cap-1)`；负载因子 0.75 触发 2 倍扩容 rehash。**字符串题**：单词反转（先整体再逐词）、atoi（用 long 提前判溢出）、最长回文（中心扩展）、大数相加（模拟进位）、全排列去重（排序 + used）。
### 12.5 一句话速记
`并发手撕三件套：交替打印用 Semaphore/wait、线程池说清四要素与拒绝、LRU 用哈希 + 双向链表。`
## 13. 算法面试策略
### 13.1 核心原理
45 分钟手撕的打分维度：思路清晰度、代码正确性、边界处理、复杂度分析、沟通与响应提示——所以"先讲后写"几乎总是优于闷头写。
### 13.2 面试问答
**Q1：拿到题前 3 分钟做什么？**
A：复述题意并确认输入输出、数据范围与特殊约束；给 1~2 个例子（含边界）手工推演；说清暴力解与优化方向及复杂度；确认后再动手。
**Q2：如何口述思路？**
A：固定句式——"这题我用____；状态/指针含义是____；每步做____；时间 O(?) 空间 O(?)；边界有____"，先给骨架再补实现。
**Q3：遇到完全不会的题、以及白板/在线编程要注意什么？**
A：不会时诚实说明没做过，但立刻给出可推进部分（暴力解、特殊情形解、优化方向），把问题拆小并主动要提示，绝不编造结论；在线编程注意方法与签名与题目一致、先跑样例，白板预留修改空间、不省边界判断，写完自己过"空/单元素、常规、极端"三个用例。
### 13.3 高频追问与陷阱
- "写完就完"是最大失分点，必须补复杂度、可优化点与边界；被追问"海量数据/并发"时要能联系分治、外排序、位图、布隆过滤器。
### 13.4 示例
`口述模板：题意确认 → 暴力解与复杂度 → 优化思路（单调性/哈希/前缀和）→ 状态定义 → 复杂度 → 边界（空、单元素、全相同、溢出）。`
### 13.5 一句话速记
`先确认范围、再讲思路、后写代码、最后验边界与复杂度；不会就问，别沉默。`
## 自测题（含答案要点）
1. 均摊复杂度的典型例子？动态数组扩容（均摊 O(1)）、并查集路径压缩、`ArrayDeque` 操作；建堆复杂度是 O(n)，因为高度 h 的节点数约 n/2^(h+1)，求和得 O(n)。
2. 快排最坏场景与避免手段？有序数组 + 固定基准 → O(n²)；随机化/三数取中/小区间插排/深度超限转堆排。
3. 归并排序两个不可替代的优势？稳定；适合链表与外排序。
4. 二分查找防死循环的关键？取整方向与边界收缩方式必须一致。
5. 滑动窗口失效的场景？元素含负数时"和"不再单调；改用前缀和 + 哈希。
6. 0-1 背包为何容量倒序？保证每件物品只用一次（读取上一轮状态）。
7. LIS 的 O(n log n) 核心？维护最小结尾数组 tails + 二分替换。
8. Dijkstra 的限制与替代？不能处理负权；用 Bellman-Ford/SPFA 或 DAG 拓扑 + 松弛。
9. Kahn 算法如何判环？输出节点数 < 总节点数即存在环。
10. 单例 DCL 为什么必须 volatile？防止"分配内存→赋值引用→初始化"重排导致其他线程拿到半初始化对象。
11. 线程池 execute 的完整流程？core 满 → 入队 → 队列满 → 扩到 max → 拒绝策略。
12. LRU 与 LFU 的结构差异？LRU 哈希 + 双向链表；LFU 频次桶 + 频次内 LRU 顺序，需维护 minFreq；令牌桶允许突发而漏桶输出速率恒定。
## 背诵卡片
1. 复杂度排序：O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ)。
2. n ≤ 10⁵ 一般要 O(n log n)；n ≤ 20 可状压。
3. 均摊是确定性上界，平均依赖概率分布；递归空间 = 递归深度。
4. 建堆 O(n)，逐个插入建堆 O(n log n)。
5. HashMap 负载因子 0.75、容量 2 的幂、树化阈值 8。
6. 跳表是 Redis ZSet 的底层，实现简单 + 范围查询友好。
7. 并查集 = 路径压缩 + 按秩合并 ≈ O(α(n))。
8. Top K 用小顶堆（保留最大的 k 个）；中位数用双堆。
9. 稳定排序：冒泡、插入、归并、计数、基数、桶；不稳定排序：选择、希尔、快排、堆排。
10. Java 基本类型排序用双轴快排，对象用 TimSort（稳定）。
11. 二分防溢出：`(l + r) >>> 1`；取整方向与收缩方向必须一致。
12. lower_bound：`a[m] >= t ? r = m : l = m + 1`（左闭右开）。
13. 最长窗口用 if 收缩，最短窗口用 while 收缩。
14. 三数之和去重：排序 + 跳过相同元素。
15. 前缀和初始化 `pre[0] = 0`，长度 n+1；差分 `diff[l] += v; diff[r+1] -= v`。
16. 回溯 = 选择 + 递归 + 撤销选择；组合去重先排序再跳过同层相同值。
17. 0-1 背包容量倒序，完全背包正序。
18. 背包求"恰好装满"初始化 -∞，求"至多"初始化 0。
19. LIS 用 tails + 二分；编辑距离"相同取左上，不同 1+min(上/左/左上)"。
20. 股票问题用 hold/free 状态机统一建模。
21. 拓扑排序：入度 0 入队，输出不足说明有环。
22. 无权图最短路用 BFS；Dijkstra 用堆 O(E log V) 并可懒惰删除。
23. Kruskal = 边排序 + 并查集；Prim = 堆 + 已选集合。
24. `x & (x-1)` 清最低位 1，`x & -x` 取最低位 1。
25. Java 无符号右移用 `>>>`，移位次数按 32 取模。
26. DCL 单例必须有 volatile；枚举单例最安全。
27. 等待条件永远用 while；唤醒优先 notifyAll 或双 Condition。
28. LRU = HashMap + 双向链表 + 哨兵节点。
29. 线程池四要素：核心数、最大数、队列、拒绝策略。
30. 手撕流程：确认范围 → 举例 → 讲思路 → 写代码 → 验边界 → 报复杂度。
