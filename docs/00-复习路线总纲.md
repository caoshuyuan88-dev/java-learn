# Java 后端面试复习路线总纲

> **定位**：整套复习资料的入口。给出岗位能力模型、分阶段复习路线、三种周期的排期表、每日时间盒与进度追踪表。
> **适用人群**：Java 后端开发（社招 3-5 年为主，1-2 年与校招同样可用，只需调整深度与时长）。
> **建议复习时长**：本文件自身 1 小时，后续按路线执行 4~12 周。
> **关联文档**：全部 38 篇分册见文末「进度追踪表」，目录索引见 [README](../README.md)。

### 0.2 单篇文档统一结构

每篇分册都是同一个骨架，便于按同一节奏推进：

| 小节 | 作用 | 使用方式 |
| --- | --- | --- |
| `0. 知识地图` | 知识点 + 重要度 + 常考形式 | 先扫一遍，决定取舍与顺序 |
| `1.x 核心原理` | 讲清 why / how，带阈值与源码要点 | 精读，边读边画图 |
| `1.x 面试问答` | Q/A 形式，答案是"能直接背的" | 合上文档自问自答，答不上就标记 |
| `1.x 高频追问与陷阱` | 面试官的第二层、第三层追问 | 用来判断自己是"背了"还是"懂了" |
| `1.x 一句话速记` | 3 行以内的结论 | 面试当天扫读 |
| `自测题` | 12~20 题，带答案要点 | 每阶段结束时做，错题进错题本 |
| `背诵卡片` | 30~40 条一行速记 | 面试前 30 分钟扫读专用 |

### 0.3 复习闭环（每篇文档都走这五步）

```
① 扫知识地图（3 分钟）→ ② 精读原理（30-60 分钟）→ ③ 合文档自问自答（15 分钟）
→ ④ 写 3-5 条自己的话的总结 + 1 个可运行 demo / 或口述方案（15 分钟）→ ⑤ 做自测题，错题进错题本
```

**关键判断标准**：能对着空白纸把某个机制的流程、阈值、失效场景、对比方案讲出来，才算过。只看懂不算过。

### 0.4 三种周期，对号入座

| 周期 | 适用情况 | 每天投入 | 取舍策略 |
| --- | --- | --- | --- |

## 2. 六阶段路线总览

阶段是**能力递进**关系，编号即推荐顺序。计算机基础（阶段 6）建议**贯穿全程**而不是集中攻。

| 阶段 | 主题 | 核心产出 | 建议时长（8 周版） | 进入下一阶段的检查点 |
| --- | --- | --- | --- | --- |
| 阶段 0 | 定位与诊断 | 自评矩阵、目标岗位 JD 拆解、简历初稿 | 1~2 天 | 能说出 3 个最弱模块并排出补漏顺序 |
| 阶段 1 | Java 内功 | 5 篇分册笔记 + 错题本 | 1.5 周 | 并发与 JVM 能从内存模型讲到排查流程 |
| 阶段 2 | 数据层 | MySQL 3 篇 + Redis 2 篇 | 1.5 周 | 能画 B+ 树、讲 MVCC、说清缓存一致性方案 |
| 阶段 3 | 框架 | Spring 5 篇 | 1.5 周 | 能手画 Spring 启动流程与 Bean 生命周期 |
| 阶段 4 | 中间件 | MQ + ES + Nginx + ZK | 1 周 | 能回答 MQ 四连问与选型对比 |
| 阶段 5 | 分布式与架构 | 分布式 5 篇 + 系统设计 | 1 周 | 能对任一系统设计题给出分层方案与取舍 |
| 阶段 6 | 计算机基础 | 网络、OS、算法、Linux | 贯穿全程，每天 1h | 算法保持手感，网络问答能到追问层 |
| 阶段 7 | 工程化与 DevOps | 4 篇（选学） | 0.5 周 | 能讲清一次完整发布链路与线上排查链路 |
| 阶段 8 | 面试实战 | 简历定稿 + 话术 + 模拟面试 | 1 周 | 模拟面试能过 80% 的问题，项目 3 分钟讲完 |

**阶段依赖关系**：阶段 1 → 阶段 3（Spring 源码需要并发与反射基础）；阶段 2 → 阶段 5（分布式事务依赖 MySQL 事务与锁）；阶段 3 → 阶段 4（MQ 的 Spring 集成需要框架基础）。阶段 6 与阶段 2 无依赖，可并行。

## 3. 各阶段详解

### 阶段 0：定位与诊断（1~2 天）

**目标**：避免"从第一页开始背"的低效复习，先确定打哪里。

要做的事：
1. 找 3~5 个目标岗位的真实 JD，把要求的技术点逐条抄下来，合并成一张"必须会"清单，与 [1.1 技术栈地图](#11-技术栈地图与考察权重) 对照，缺的标红。
2. 完成 [1.2 自评矩阵](#12-自评矩阵开始复习前先做一次)。
3. 写简历初稿（见 [简历与项目表达](./08-面试实战/01-简历与项目表达.md)），简历是复习的导航图：简历上写了的必须能答，答不了的要么删要么补。
4. 定周期（4/8/12 周），把排期表贴到日历上。

**检查点**：能用一句话回答"我这次面试最可能挂在哪三个点上"。

### 阶段 1：Java 内功（必答区，1.5 周）

**目标**：把语言层的"根"打牢。这一层不过关，后面所有框架问题都会露怯。

| 顺序 | 文档 | 关键交付 |
| --- | --- | --- |
| 1 | [01-Java语言核心与面向对象](./01-Java基础/01-Java语言核心与面向对象.md) | equals/hashCode 契约、泛型擦除、动态代理对比表 |
| 2 | [02-集合框架](./01-Java基础/02-集合框架.md) | 手画 HashMap put/resize 流程、ConcurrentHashMap JDK8 结构 |
| 3 | [03-并发编程](./01-Java基础/03-并发编程.md) | 手画线程池执行流程图、AQS 队列、手写 DCL 单例 |
| 4 | [04-JVM与GC调优](./01-Java基础/04-JVM与GC调优.md) | 手画 JVM 内存分区、G1 Region、写一份 CPU 100% 排查步骤 |
| 5 | [05-Java新特性与语言演进](./01-Java基础/05-Java新特性与语言演进.md) | Stream 常用操作速查、虚拟线程适用场景 |

**必须能不假思索回答的 10 个问题**：
1. `==` 和 `equals` 的区别，重写 equals 为什么必须重写 hashCode？
2. HashMap 的容量为什么是 2 的幂？扩容时链表怎么拆？
3. ConcurrentHashMap 在 JDK 7 和 8 分别怎么保证线程安全？
4. `volatile` 保证了什么、没保证什么？DCL 单例为什么必须加 volatile？
5. synchronized 锁升级的过程，以及它和 ReentrantLock 的区别？
6. 线程池的 7 个参数、执行流程、4 种拒绝策略？核心线程数怎么定？
7. ThreadLocal 为什么会内存泄漏？
8. JVM 运行时数据区有哪些，JDK 8 之后方法区有什么变化？
9. CMS 和 G1 的区别，G1 为什么能可预测停顿？
10. 线上 CPU 100% 你怎么排查？（要求能说出完整命令链）

**常见坑**：把"背结论"当"会"。判断标准是能否回答追问——例如答完"线程池先核心后队列再最大线程"，还要能答"为什么这么设计""队列满了但线程数没到 max 会怎样"。

### 阶段 2：数据层（1.5 周）

**目标**：MySQL 与 Redis 是后端面试区分度的主要来源，必须做到"能给数字、能给方案、能给排查步骤"。

| 顺序 | 文档 | 关键交付 |
| --- | --- | --- |
| 1 | [01-MySQL体系结构与索引](./02-数据库/01-MySQL体系结构与索引.md) | 手画 B+ 树结构、EXPLAIN 字段解读、索引失效清单 |
| 2 | [02-MySQL事务锁与MVCC](./02-数据库/02-MySQL事务锁与MVCC.md) | 画出 undo 版本链 + ReadView 判断流程、加锁规则表 |
| 3 | [03-MySQL调优主从与分库分表](./02-数据库/03-MySQL调优主从与分库分表.md) | 一份慢 SQL 优化案例、分库分表迁移方案 |
| 4 | [04-Redis数据结构与核心原理](./02-数据库/04-Redis数据结构与核心原理.md) | 数据类型与编码转换表、持久化与复制流程 |
| 5 | [05-Redis高可用与缓存治理](./02-数据库/05-Redis高可用与缓存治理.md) | 缓存三大问题的方案对比、缓存一致性方案选型 |

**必须能回答**：最左前缀原理与失效场景、`Using index` 与 `Using filesort` 的含义、RR 下幻读有没有被解决、间隙锁什么时候加、RC 与 RR 的 ReadView 差异、深分页怎么优化、Redis 为什么快、AOF 与 RDB 怎么选、Redis 主从与 Cluster 的区别、缓存穿透/击穿/雪崩的区别与方案、缓存与数据库一致性怎么做。

**常见坑**：只讲现象不讲机制（比如"加了索引就快了"），以及把 Redis 当"缓存工具"而答不出其数据结构与集群机制。

## 5. 复习方法论

### 5.1 三种无效复习 vs 三种有效复习

| 无效做法 | 为什么无效 | 替代做法 |
| --- | --- | --- |
| 从头到尾看视频/文档 | 输入不等于会，被动接收留存率低 | 每 30 分钟停下来合上材料自述一遍 |
| 背结论数字 | 追问两层就崩 | 每个结论都补上"为什么"和"如果不这样会怎样" |
| 只刷题不总结 | 换个题就不会 | 按专题刷，每题写 3 行"题型 + 套路 + 边界" |
| 只准备不会的 | 会的也可能忘 | 每 3 天做一次"复习旧内容"而不是只学新的 |
| 项目话术临时编 | 追问必崩 | 提前画架构图、备好数据与故障案例 |

### 5.2 面试官视角的四层追问模型

任何问题都可能被追问到四层，**准备时按四层检查**：

| 层级 | 追问形态 | 例子（线程池） |
| --- | --- | --- |
| L1 是什么 | 定义、结论 | 线程池的 7 个参数是什么 |
| L2 为什么 | 设计动机、原理 | 为什么先入队列而不是直接开线程 |
| L3 怎么用/怎么排查 | 实践、取舍 | 核心线程数怎么定？线上线程池打满怎么办 |
| L4 边界与替换 | 失效场景、替代方案 | 队列用无界会怎样？和 ForkJoinPool 的区别 |

**判断自己是否"过关"的标准**：能主动讲到 L3/L4，而不是等面试官问。

### 5.3 输出型学习法（本套资料的核心用法）

1. **费曼输出**：把每个专题讲给"不懂的人"，讲不通的地方就是盲区。
2. **白纸还原**：合上文档，在空白纸上画出流程/结构（Bean 生命周期、MVCC 版本链、秒杀架构）。
3. **最小可运行 demo**：并发（自己压线程池）、Redis（本地起一个做缓存一致性实验）、MQ（本地跑通顺序消息与事务消息）、MySQL（造 100 万行数据验证索引）。
4. **追问链笔记**：每个知识点记一条"追问链"，例如 `synchronized → 锁升级 → Mark Word → 对象头结构 → 偏向锁撤销`。
5. **错题本**：只记"我答不出的问题 + 一句话答案 + 关联文档"，面试前只过错题本。

### 5.4 笔记与复盘模板

### 今天答不出的问题（进错题本）
### 需要动手验证的点

## 7. 常见失败模式与对策

| 失败模式 | 典型表现 | 对策 |
| --- | --- | --- |
| 广度陷阱 | 什么都看一点，一问就浅 | 先按权重打 5 星模块，再做加法 |
| 深度陷阱 | 死磕某个源码细节，进度停滞 | 源码只读"面试会问的 20% 关键路径" |
| 只看不练 | 笔记很厚，开口就卡 | 强制输出：录音、白纸还原、对练 |
| 项目失真 | 答不出数据量与细节 | 提前把项目数据（QPS、数据量、耗时）量化并背下来 |
| 答非所问 | 面试官问 A，讲了 5 分钟 B | 先复述问题、给结论、再展开（总—分—总） |
| 只会背不会想 | 追问两层就崩 | 用 [5.2 四层追问模型](#52-面试官视角的四层追问模型) 自查 |
| 节奏失控 | 前松后紧，面试通知来了还没复习完 | 用 8 周表倒排，面试集中在最后两周 |
| 心态崩盘 | 一次被拒就停摆 | 面试是采样，记录复盘，按周迭代 |

## 8. 冲刺清单

### 8.1 面试前 7 天

- [ ] 过一遍 [高频八股速查手册](./08-面试实战/02-高频八股速查手册.md) 全部条目，把答不出的标红
- [ ] 项目三版话术各讲 3 遍并录音
- [ ] 完成至少 1 次完整模拟面试（技术 + 项目 + 反问）
- [ ] 复盘错题本，只过错的
- [ ] 每天保持 1~2 道算法手感
- [ ] 确认面试形式（电话/视频/现场）、时长、面试官角色、是否手写代码

### 8.2 面试前 24 小时

- [ ] 扫读 5 星模块的「背诵卡片」
- [ ] 复习自己的简历，确保每一条都能展开讲 3 分钟
- [ ] 准备 3 个反问问题（按面试官角色）
- [ ] 准备 2 个自己的"亮点案例"（一个技术攻坚、一个协作推动）
- [ ] 确认设备/网络/安静环境，准备纸笔（要写代码时用得上）
- [ ] 早睡。状态比多背 10 个知识点重要

### 8.3 面试前 1 小时

- [ ] 只看「背诵卡片」与「知识地图」，不学新东西
- [ ] 默念一遍自我介绍（出声）
- [ ] 深呼吸，提醒自己：**先给结论，再讲原因，最后给边界**；不会的题先讲思路
